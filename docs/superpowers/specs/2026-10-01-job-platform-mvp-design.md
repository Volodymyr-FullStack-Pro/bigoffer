# Job Platform — Подпроект 1: Фундамент + Поиск работы (MVP)

**Дата:** 2026-10-01
**Статус:** дизайн утверждён, ожидает ревью спеки
**Продукт:** **BigOffer** (домен `getbigoffer.com` — купить перед продакшеном; до этого — бесплатные поддомены Vercel/Netlify)

## 1. Цель

Платформа, в которую пользователь заходит каждый день и видит свежие, отобранные под его профиль вакансии со всех ключевых площадок, быстро их просматривает, откликается и ведёт отклики на канбан-доске.

- **Сейчас:** первый пользователь — автор (Full-Stack, React/Next.js/TS/Node/NestJS, 3+ года, English B2, Украина, remote).
- **Потом:** коммерческий SaaS для **любых профессий** (не только IT) на рынках Украины/СНГ + международный remote.

Каждое архитектурное решение должно работать для одного пользователя сегодня и для тысяч — без переписывания.

### Критерии успеха MVP

1. Каждое утро в Telegram приходит дайджест, по ссылке открывается лента «Сегодня» с вакансиями, отсортированными по совпадению.
2. В ленте вакансии из всех источников MVP, без дублей, с AI-резюме на языке пользователя.
3. Вакансию можно за один жест сохранить на доску, на доске — перетаскивать между колонками.
4. При открытии вакансии сразу готов «набор отклика» (письмо, короткое сообщение, ответы на вопросы формы, контакты в один клик) — отклик занимает < 1 минуты.
5. Вся переписка с рекрутером, лейблы и причины отказов хранятся в карточке; приложение само напоминает о follow-up и показывает, что улучшить.
6. Интерфейс полностью на uk / ru / en, светлая и тёмная тема.
7. Данные одного пользователя недоступны другому (проверено тестами RLS).

- Автоматическая отправка follow-up писем — только черновик + копирование.
- Парсинг LinkedIn с сервера под аккаунтом пользователя (нарушение ToS, бан аккаунта пользователя).

- Организации/команды, биллинг. Поле `profiles.plan` есть, `org_id` добавится миграцией.
- Web Push — после MVP (в MVP канал уведомлений — Telegram).
- Перевод полного текста вакансий (переводится только AI-резюме; кнопка «перевести» — после MVP).

## 5. Модель данных

### 5.1 Принцип мультитенантности

- **Глобальные таблицы** (`roles`, `skills`, `sources`, `companies`, `jobs`, `job_postings`, `search_queries`, `source_runs`): `SELECT` — любому `authenticated`; запись — только `service_role` (воркеры). `source_runs` — только service_role/админ.
- **Пользовательские таблицы**: RLS `user_id = auth.uid()` на все операции.
- Одна вакансия хранится один раз, сколько бы пользователей её ни видели.

### 5.2 Справочники

```sql
roles   (id, slug UNIQUE, name jsonb {uk,ru,en}, category text)
skills  (id, slug UNIQUE, name jsonb, aliases text[])
sources (id text PK, name, kind: 'html'|'api'|'rss'|'email',
         enabled bool, min_interval_minutes int, paused_until timestamptz)
```

### 5.3 Вакансии (глобальные)

```sql
companies    (id, name, normalized_name UNIQUE, website, logo_url)
jobs         (id, fingerprint UNIQUE, title, company_id, description_text,
              location, remote_type: 'remote'|'hybrid'|'office'|'unknown',
              salary_raw, posted_at, first_seen_at, last_seen_at,
              status: 'active'|'expired',
              -- обогащение (LLM, один раз на вакансию):
              role_id, seniority: 'intern'|'junior'|'middle'|'senior'|'lead'|null,
              skills text[], salary_min_usd int, salary_max_usd int,
              lang text, summary jsonb {uk,ru,en}, enriched_at, enrich_error text)
job_postings (id, job_id, source_id, external_id, url, seen_at,
              UNIQUE(source_id, external_id))
```

Индексы: `pg_trgm` GIN на `jobs.title`; `(status, first_seen_at desc)`; GIN на `jobs.skills`.

### 5.4 Сбор по запросам

```sql
search_queries (id, source_id, query_key UNIQUE, params jsonb,
                last_run_at, next_run_at)
source_runs    (id, source_id, query_id, status: 'ok'|'error'|'blocked',
                found int, inserted int, error text, started_at, finished_at)
```

`query_key` — детерминированный хэш нормализованных `params` + `source_id`. Сто пользователей с одинаковым запросом = одна строка, один запуск.

### 5.5 Пользователь

```sql
profiles        (id = auth.users.id PK, full_name, locale: 'uk'|'ru'|'en',
                 timezone, telegram_chat_id, inbound_email_token UNIQUE,
                 digest_hour int default 9, plan text default 'free',
                 contacts jsonb,       -- email, phone, linkedin, github, portfolio, telegram
                 follow_up_days int[] default '{5,10}',  -- рабочие дни после отклика
                 ghost_after_days int default 21,
                 onboarded_at)
search_profiles (id, user_id, name, role_id, keywords text[],
                 exclude_keywords text[], seniority text[], locations text[],
                 remote_type, salary_min_usd int, is_active bool)
search_profile_queries (search_profile_id, search_query_id, PK both)
resumes         (id, user_id, storage_path, parsed jsonb, is_primary bool)
letter_templates(id, user_id, name, body text, locale)
answer_bank     (id, user_id, key text, question text, answer jsonb {uk,ru,en},
                 updated_at)   -- переиспользуемые ответы: зарплатные ожидания,
                               -- срок выхода, почему ищу работу, уровень English…
apply_kits      (id, user_id, job_id, cover_letter text, short_message text,
                 form_answers jsonb [{question, answer}], requirements jsonb,
                 salary_hint text, lang text, generated_at,
                 UNIQUE(user_id, job_id))
job_matches     (id, user_id, job_id, search_profile_id, score smallint,
                 breakdown jsonb, explanation jsonb {uk,ru,en},
                 state: 'new'|'seen'|'hidden'|'saved', created_at,
                 UNIQUE(user_id, job_id))
```

### 5.6 Канбан

```sql
board_columns      (id, user_id, key, title jsonb, position int,
                    kind: 'active'|'won'|'lost')
applications       (id, user_id, job_id NULL, column_id, rank text,
                    title, company, url,          -- снапшот; job_id NULL = ручная карточка
                    source_id NULL,               -- через какую площадку откликнулся
                    applied_at, next_action_at, salary text, notes text,
                    contact jsonb,                -- рекрутер: имя, email, linkedin, telegram
                    letter_used text, letter_kind: 'full'|'short'|'none'|null,
                    -- ответы и follow-up:
                    first_response_at, last_activity_at,
                    follow_up_count smallint default 0, next_follow_up_at,
                    -- итог:
                    outcome: 'open'|'offer'|'rejected'|'withdrawn'|'ghosted' default 'open',
                    rejection_stage: 'application'|'screening'|'technical'|'test_task'
                                     |'final'|'offer'|null,
                    rejection_by: 'company'|'me'|null,
                    rejection_reasons text[],     -- ключи таксономии (см. 7.4)
                    rejection_note text,
                    created_at, updated_at)
labels             (id, user_id, key text NULL, name text NULL, color,
                    CHECK (key IS NOT NULL OR name IS NOT NULL))
                    -- key = стандартный лейбл (перевод из i18n), name = пользовательский
application_labels (application_id, label_id, PK both)
application_messages (id, application_id, user_id,
                    direction: 'in'|'out', channel: 'email'|'linkedin'|'djinni'
                    |'telegram'|'call'|'other',
                    author text, body text, sent_at,
                    inbound_email_id NULL,
                    ai_classification: 'rejection'|'interview_invite'|'test_task'
                    |'question'|'offer'|'other'|null,
                    ai_extracted jsonb)           -- дата интервью, контакт, причина отказа
application_events (id, application_id, user_id,
                    type: 'created'|'moved'|'note'|'message'|'label'
                    |'follow_up_sent'|'reminder'|'outcome',
                    payload jsonb, created_at)
inbound_emails     (id, user_id, from_addr, subject, storage_path,
                    parsed_as: 'linkedin_alert'|'djinni_alert'|'forward_verification'|'unknown',
                    jobs_extracted int, received_at)
```

- Колонки по умолчанию создаются триггером при создании профиля: **Сохранено → Откликнулся → Тестовое → Интервью → Оффер (won) → Отказ (lost)**.
- `rank` — fractional indexing (библиотека `fractional-indexing`): перетаскивание обновляет одну строку.
- `application_events` — источник истории карточки и будущий триггер для подпроекта 2 («перешла в Интервью → план подготовки»).
- **Колонка ≠ лейбл ≠ итог.** Колонка — этап воронки; `outcome` — структурированный итог для аналитики; лейблы — свободные теги пользователя (по умолчанию: «Приоритет», «Реферал», «Через рекрутера», «Зарплата не указана», «Ожидаю интервью»). Системные бейджи вычисляются, а не хранятся: «Пора напомнить», «Нет ответа N дн.», «Ghosted».
- Перенос в колонку kind=`lost` открывает диалог отказа; kind=`won` ставит `outcome='offer'`.

### 6.2 Контракт адаптера

```ts
interface SourceAdapter {
  id: SourceId;
  kind: 'html' | 'api' | 'rss';
  /** Нормализует параметры поиска пользователя в параметры источника. */
  toQueryParams(input: SearchInput): Record<string, unknown> | null; // null = источник не подходит
  search(params: Record<string, unknown>, ctx: AdapterContext): AsyncIterable<RawJob>;
}
```

`AdapterContext` предоставляет `fetch` с rate-limit, ретраями, User-Agent и логированием. Адаптер не пишет в БД.

### 6.3 Этапы

1. **Normalize** — `RawJob` → Zod → `NormalizedJob`. Невалидная запись пропускается с логом, выдача не падает.
2. **Dedupe** — `fingerprint = sha256(normalize(company) | normalize(title) | regionBucket)`. При промахе — fallback: та же компания + `similarity(title) > 0.9` (pg_trgm) за 14 дней. Совпадение → новый `job_posting` к существующему `job`, обновить `last_seen_at`.
3. **Enrich** (только новые jobs) — Claude Haiku 4.5, structured output по Zod-схеме: роль, грейд, навыки (маппинг на `skills.aliases`), зарплата → USD, remote_type, язык, `summary {uk,ru,en}` (2 предложения). Системный промпт кэшируется. Ошибка → `enrich_error`, вакансия всё равно матчится по ключевым словам.
4. **Match** — для каждого активного `search_profile`, к которому привязан запрос:

   | Компонент | Вес | Логика |
   |---|---|---|
   | Навыки | 35 | доля навыков профиля, найденных в `jobs.skills` / тексте |
   | Роль | 25 | совпадение `role_id` или ключевых слов в заголовке |
   | Грейд | 15 | точное = 15, соседний = 8, иначе 0, неизвестен = 8 |
   | Локация/remote | 15 | совместимость `remote_type` и `locations` |
   | Зарплата | 10 | `salary_max_usd >= salary_min_usd` = 10, неизвестна = 5 |

   `exclude_keywords` в заголовке/тексте → `state = 'hidden'`. `breakdown` сохраняется для UI.
5. **Explain** — один раз в день на пользователя для топ-20 новых `job_matches`: LLM пишет 1 строку «почему подходит» на `profiles.locale`.
6. **Pre-generate apply kits** — для новых `job_matches` со `score >= 70` (лимит 20/день/пользователь в free) фоново создаётся `apply_kit`, чтобы при открытии вакансии всё было готово мгновенно. Для остальных kit генерируется при открытии (стриминг, ~2–3 c).

### 6.4 Планирование и защита от банов

- `schedule-queries` ежечасно; каждый запрос запускается не чаще `sources.min_interval_minutes` (DOU/API — 60, HTML — 120–180).
- Trigger.dev queue на источник с `concurrencyLimit: 1`, случайная пауза 1–4 c между запросами страниц.
- Ретраи: экспоненциальный backoff, 3 попытки.
- 403/429/капча → `sources.paused_until = now() + 1h` (circuit breaker), `source_runs.status = 'blocked'`.
- 3 запуска подряд с `found = 0` у исправного источника → алерт админу в Telegram (смена вёрстки).
- `expire-jobs` ежедневно: `last_seen_at < now() - 14 days` → `expired`.

### 6.5 Входящая почта

1. При онбординге пользователь получает адрес `<inbound_email_token>@in.<domain>` и инструкцию по автопересылке (Gmail / Outlook / ukr.net).
2. Cloudflare Email Worker → `POST /api/inbound-email` с HMAC-подписью.
3. Сырое письмо → Storage, строка в `inbound_emails`, задача `parse-email`.
4. Парсер по отправителю: LinkedIn Job Alerts, Djinni → список вакансий (title, company, url) → тот же конвейер (normalize → dedupe → enrich → match) с источником `linkedin` / `djinni`. Неизвестный формат → LLM-извлечение.
4a. **Письма от рекрутеров** (не алерты): матчинг к карточке по домену/имени компании, адресу контакта, названию вакансии в теме (детерминированно, затем LLM при неоднозначности) → `application_messages` (direction `in`) + AI-классификация → предложение действия в UI (см. 7.3). Не сматчилось → «Входящие без карточки» с кнопкой «Привязать / Создать карточку». Уведомления Djinni о новых сообщениях обрабатываются так же.
5. Письма подтверждения пересылки (Gmail verification) распознаются и показываются пользователю в настройках с кодом.

## 7. UX

### 7.1 Ежедневный сценарий

1. **Дайджест** в Telegram в `digest_hour` по TZ: «🔥 14 новых вакансий, 3 — 90%+» + топ-3 + кнопка «Смотреть» (deep link `/[locale]/feed/today`). Подключение бота — кнопка в настройках (deep link `t.me/<bot>?start=<token>`).
2. **Лента «Сегодня»** — `job_matches.state = 'new'` за последние 24 ч (или с последнего визита), сортировка по score.
   - **Мобайл — колода карточек**: свайп вправо → сохранить (карточка в «Сохранено»), влево → скрыть, вверх/тап → детали. Дублирующие кнопки внизу. Тост «Отменить» 5 с.
   - **Десктоп — почтовый клиент**: список слева, детали справа. Хоткеи: `J/K` навигация, `S` сохранить, `H` скрыть, `A` откликнулся, `O` открыть оригинал.
   - Прогресс «8 / 14». Пустое состояние «Всё просмотрено 🎉» + статистика дня.
   - Фильтры: профиль поиска, мин. score, remote, источник. Вкладка «Все» — архив с поиском.
3. **Карточка**: шкала совпадения, заголовок, компания + лого, зарплата, remote/город, грейд, до 5 навыков (совпавшие подсвечены), AI-резюме (2 строки), «почему подходит», иконки источников, «2 ч назад».
4. **Детали**: AI-резюме, разбор совпадения (навыки ✓/✗, breakdown), полный текст, все ссылки + справа (на мобайле — нижний лист) панель **«Набор отклика»** (7.2). Действия: Откликнуться / Сохранить / Скрыть.
5. **Доска**: колонки из `board_columns`, dnd-kit (мышь, тач с long-press, клавиатура). На карточке: компания, роль, лейблы, «откликнулся 6 дн. назад», бейджи «Пора напомнить» / «Нет ответа N дн.», иконка непрочитанного ответа. Фильтры доски: по лейблу, по источнику, «Ждут ответа», «Пора напомнить». Клик → боковая панель карточки (7.3). Кнопка «+ Добавить вручную» (вставить ссылку → парсинг вакансии по URL).
6. **Напоминания**: в дайджесте блок «Пора напомнить о себе: …» и «Ответ ждёт вашей реакции: …».

### 7.2 Набор отклика (Apply Kit)

Цель — отклик меньше чем за минуту. Открывается вместе с деталями вакансии; для score ≥ 70 уже сгенерирован (6.3 п.6), иначе стримится.

1. **Требования ✓/✗** — must-have из вакансии против профиля; red flags (например «офис 5/5», «испытательный без оплаты»).
2. **Сопроводительное письмо** — шаблон пользователя, LLM заменяет `[…]` персональной строкой (или пишет целиком, если шаблона нет). Язык = язык вакансии (переключаемо). Кнопки: Копировать / Перегенерировать / Тон (короче, формальнее) / Редактировать.
3. **Короткое сообщение** (≤ 500 символов) — для Djinni, LinkedIn InMail, Telegram рекрутеру.
4. **Контакты в один клик** — чипы: имя, email, телефон, LinkedIn, GitHub, портфолио, ссылка на CV (подписанная ссылка из Storage, 30 дней). Клик = копирование.
5. **Вопросы формы** — поле «Вставьте вопросы из формы отклика» (один или весь текст формы) → LLM разбирает на вопросы и отвечает, используя профиль, CV и `answer_bank`. Каждый ответ — копировать / править; правка предлагает «Сохранить в банк ответов». Типовые вопросы (зарплата, срок выхода, English, почему ищу) отвечаются из банка без LLM.
6. **Подсказка по зарплате** — по вилке вакансии (если есть) и `salary_min_usd`.
7. **Откликнуться** — открывает оригинал; при возврате (`visibilitychange`) — «Откликнулись?» → «да» создаёт/перемещает карточку в «Откликнулся» с `applied_at`, `source_id`, `letter_used`, `letter_kind`; ставит `next_follow_up_at` по `profiles.follow_up_days`.

### 7.3 Карточка отклика (боковая панель)

Вкладки:
- **Обзор** — вакансия (ссылка), колонка, лейблы (добавить/создать с цветом), рекрутер-контакт, зарплата, `next_action_at` (дата интервью и т.п.), заметки, использованное письмо.
- **Переписка** — лента сообщений (входящие/исходящие) по всем каналам. «+ Добавить сообщение»: вставить текст, выбрать канал и направление (по умолчанию определяется AI). Письма, пересланные на inbound-адрес, попадают сюда автоматически. Каждое входящее классифицируется AI; при `interview_invite` / `test_task` / `rejection` / `offer` показывается **предложение действия**: «Перенести в Интервью и поставить дату 12.10 14:00?», «Отметить отказ: причина — недостаточный English?» — применяется одним кликом, никогда без подтверждения.
- **Follow-up** — счётчик, дата следующего напоминания, кнопка «Сгенерировать follow-up» (язык и канал — как у переписки), «Отправил» → исходящее сообщение + `follow_up_count++` + следующая дата.
- **История** — `application_events`.

### 7.4 Отказы и follow-up — правила

- **Диалог отказа** (перенос в «Отказ» или принятие AI-предложения): этап (`rejection_stage`), кто отказал (`rejection_by`), причины — мультивыбор из таксономии + свободный текст + вставка письма рекрутера.
- **Таксономия причин** (ключи, переводы в i18n): `experience_level`, `stack_mismatch`, `english`, `salary_expectations`, `position_closed`, `other_candidate`, `test_task_failed`, `tech_interview_failed`, `location_timezone`, `culture_fit`, `no_feedback`, `my_decision_salary`, `my_decision_company`, `other`.
- **Follow-up по умолчанию**: напоминание через 5 и 10 рабочих дней после отклика без входящих сообщений; через 21 день — предложение отметить `ghosted` (outcome, причина `no_feedback`). Любое входящее сообщение сбрасывает таймер и ставит `first_response_at`.
- Ежедневная задача `follow-up-scan` вычисляет `next_follow_up_at`, бейджи и блок для дайджеста.

### 7.5 Аналитика (MVP-lite)

Страница «Аналитика» (пункт в навигации):
- Воронка: сохранено → откликнулся → ответ → интервью → оффер, с конверсиями.
- Response rate и время до первого ответа — по источнику, роли, типу письма (`full`/`short`/`none`), score-бакету.
- Отказы: разбивка по `rejection_stage` и `rejection_reasons`; доля ghosted.
- Активность: плитка в стиле GitHub (просмотры/отклики по дням).
- **Еженедельный AI-инсайт** (воскресенье, в дайджесте и на странице): 3 наблюдения + 3 конкретных действия на основе агрегатов (например «60% отказов на этапе technical — причина stack_mismatch по NestJS: подтяните X или фильтруйте вакансии»). LLM получает только агрегаты, не сырые письма.

### 7.6 Онбординг

1. Регистрация (magic link или Google).
2. Выбор языка (предзаполнен из `Accept-Language`; язык по умолчанию — английский).
3. Загрузка CV (PDF) → LLM-парсинг → предзаполненный профиль поиска (роль, навыки, грейд, локации, языки).
4. Правка профиля поиска + стоп-слова.
5. Шаблон сопроводительного письма (предзаполнен заготовкой; плейсхолдер `[…]`).
6. Подключение Telegram и адреса для пересылки (можно пропустить).
7. Первый сбор запускается немедленно; экран «Собираем вакансии…» с live-счётчиком через Realtime.

### 7.7 Оболочка и навигация

- Десктоп — боковая панель: **Сегодня / Доска / Аналитика / Подготовка (скоро) / Профиль**; мобайл — нижний таб-бар: **Сегодня / Доска / Подготовка / Профиль** (Аналитика — внутри Профиля).
- Шаг онбординга 5 дополнительно предлагает заполнить контакты и 5 базовых ответов `answer_bank` (зарплата, срок выхода, English, почему ищу работу, формат работы).
- В шапке: переключатель языка (UK/RU/EN) и темы (светлая/тёмная/системная). Выбор языка сохраняется в `profiles.locale` и cookie.
- PWA (manifest + иконки) — устанавливается на телефон.

### 7.8 Визуальный стиль — «Neo-brutal Job Zine»

Вдохновлён syntax.fm (тёмная база, один кислотный акцент, моно-шрифт, шум-текстура, толстые рамки), но своя айдентика и дружелюбность к не-IT.

- **Шрифты** (все с кириллицей): **Unbounded** — заголовки; **Onest** — основной текст; **JetBrains Mono** — только мета (зарплата, время, score, теги).
- **Цвет**: тёмная тема — графит `oklch(16% 0 0)`; светлая — тёплая бумага `#F4F1E8`. Акцент — кислотный лайм `#C6F432`; вторичный (AI-функции) — электрический фиолетовый `#7B5CFF`; статусы: success (оффер), coral (отказ), amber (напоминание). Шкала серых — OKLCH.
- **Фактура**: шум-текстура (SVG) на фоне; рамки 2px; жёсткие смещённые тени `4px 4px 0`; кнопка «вдавливается» при нажатии (тень → 0, translate).
- **Фирменные элементы**: карточки-стикеры с наклоном при свайпе и штампом **SAVED / APPLIED**; шкала совпадения в стиле VU-метра (сегменты); колонки доски как стопки стикеров; конфетти при переносе в «Оффер»; плитка активности в стиле GitHub (просмотры/отклики за день).
- **Токены**: CSS-переменные через Tailwind v4 `@theme` поверх shadcn/ui; структура допускает дополнительные цветовые скины.
- **Доступность**: WCAG AA в обеих темах; `prefers-reduced-motion` отключает анимации; у каждого свайпа есть кнопка; доска управляется с клавиатуры.

## 8. i18n

- UI: next-intl, язык по умолчанию — `en` (uk/ru — переключателем и по `Accept-Language`), сообщения в `apps/web/messages/{uk,ru,en}.json`; ключи типизированы; CI проверяет, что все локали содержат одинаковые ключи.
- Контент: поля `jsonb {uk,ru,en}` (роли, навыки, колонки, AI-резюме). Хелпер `t(field, locale)` с фолбэком `locale → en → первый доступный`.
- Тексты вакансий не переводятся; AI-резюме и пояснения — на языке пользователя.
- Даты/числа/валюты — `Intl` по локали.

## 9. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Невалидная запись из источника | пропуск + лог, остальная выдача обрабатывается |
| Источник блокирует (403/429/капча) | circuit breaker на 1 ч, `source_runs.status='blocked'` |
| Источник молча вернул 0 трижды | алерт админу в Telegram |
| LLM недоступен / невалидный JSON | ретрай 2×; затем `enrich_error`, матчинг по ключевым словам |
| Ошибка генерации письма | показать шаблон без персонализации + тост |
| Неподписанный/неверный inbound webhook | 401, без записи |
| Неизвестный формат письма | LLM-извлечение; при неудаче — `parsed_as='unknown'`, видно в настройках |
| Telegram недоставлен (бот заблокирован) | обнулить `telegram_chat_id`, баннер в приложении |
| Оптимистичное обновление доски не удалось | откат позиции + тост |
| Импорт вакансии по URL не удался (LinkedIn, логин-стена) | форма ручного ввода, предзаполненная тем, что удалось извлечь |
| Входящее письмо не сматчилось к карточке | «Входящие без карточки», ручная привязка |
| AI-классификация сообщения неуверенна | предложение действия не показывается, сообщение просто сохраняется |
| Генерация apply kit не удалась | показываются контакты, требования и шаблон без персонализации + «Повторить» |

Секреты (Supabase service key, Anthropic, Telegram, HMAC) — только в env сервера/Trigger.dev; клиент использует только anon key + RLS.

- **packages/core** — Vitest, TDD: normalize, fingerprint, regionBucket, score, email-парсеры, i18n-фолбэк, матчинг письма к карточке, расчёт follow-up дат (рабочие дни, TZ), агрегаты аналитики.
- **packages/scrapers** — тесты на сохранённых фикстурах HTML/JSON/RSS каждого источника; ежедневный канареечный прогон на живых сайтах (Trigger.dev) с алертом.
- **packages/ai** — тесты Zod-схем и маппинга ответов на фикстурах (без живых вызовов в CI).
- **БД** — SQL-тесты RLS: пользователь A не читает/не меняет данные B; `authenticated` не пишет в глобальные таблицы.
- **E2E (Playwright)** — вход → онбординг → лента → свайп/сохранение → карточка на доске → перетаскивание; набор отклика → копирование → «Откликнулись?» → карточка в «Откликнулся»; добавление сообщения → принятие AI-предложения; отказ с причинами → отражение в аналитике; прогон для трёх локалей и обеих тем (скриншоты).

## 11. Операционные заметки

- Домен продукта не выбран: до выбора inbound-адреса работают на временном домене, `<domain>` в тексте — конфиг `INBOUND_EMAIL_DOMAIN`.
- Окружения: local (`supabase start`, Trigger.dev dev), production (Supabase cloud, Vercel, Trigger.dev cloud, Cloudflare).
- Оценка стоимости MVP: Supabase Free, Vercel Hobby, Trigger.dev Free, Cloudflare Email Routing бесплатно, Haiku ~1–3 $/мес при ~300 новых вакансий/день.
- Личные файлы (`docs/*.pdf`, письма) не коммитятся — `.gitignore`.
- Соблюдение условий площадок: низкая частота, без обхода авторизации, без серверного логина в LinkedIn.

### 12.2 AI-провайдер

- Модуль `packages/ai` независим от провайдера: интерфейс `LlmClient` (структурированный JSON по Zod-схеме, поддержка изображений), реализация по умолчанию — **Gemini** (Google AI Studio). Провайдер и модель задаются env (`AI_PROVIDER`, `AI_MODEL_PUBLIC`, `AI_MODEL_PRIVATE`).
- **Два ключа по чувствительности данных:** `GEMINI_API_KEY_PUBLIC` — бесплатный тариф, только публичные данные (обогащение вакансий); `GEMINI_API_KEY_PRIVATE` — платный тариф (данные не используются для обучения) для CV, переписки, скриншотов, писем. Без приватного ключа функции с личными данными недоступны (а не падают на бесплатный).
- Заменяет упоминания Claude Haiku в 4.1 и 6.3 для MVP; Claude остаётся опцией провайдера.
- **Реализация (План 4):** обогащаются только вакансии с видимым совпадением, лучшие первыми; лимит `AI_DAILY_LIMIT` запросов/сутки, темп `AI_MIN_INTERVAL_MS`, 429 останавливает пачку. AI заполняет пробелы (грейд, формат, зарплата), но не перетирает данные источника. «Почему подходит» идёт через публичный ключ: в промпт попадают только вакансия и критерии профиля поиска (ключевые слова, навыки, грейд, формат, мин. зарплата), без имени, контактов, CV и страны. Роль хранится текстом `jobs.role` (справочник `roles` — позже). Гео-пригодность remote: `jobs.remote_regions` против `profiles.country`.

### 12.3 Умная доска (заменяет/расширяет 7.1 п.5, 7.3, 7.4)

- **Счётчики** в заголовке колонки: всего и «требует действия» (`Откликнулся · 12 · 🔴 3`).
- **Срочность карточки** (вычисляется, без AI): 🟢 свежая; 🟡 «пора пингануть» (≥5 рабочих дней без входящих); 🔴 просрочено (≥10); ⚫ «похоже на ghosting» (≥21, предложение перенести в «Отказ»); 📅 интервью ≤48 ч; ⏰ дедлайн тестового.
- **Сортировка колонки:** «Умная» (срочные вверх, подсветка) / «Вручную» (dnd rank). По умолчанию «Умная» для активных колонок.
- **Панель «Действия на сегодня»** над доской: пингануть N рекрутеров, интервью, дедлайны; каждая строка — кнопка действия. Тот же список — в утреннем Telegram-дайджесте.
- **Лейблы:** системные (вычисляемые: пора пингануть, ghosted, интервью скоро, дедлайн) + AI-лейблы при анализе («Зарплата в вилке»/«Выше бюджета», «English C1», «Тестовое», «Релокация», «Реферал», «Рекрутер ответил»); любой снимается вручную.

### 12.4 Карточки из любых каналов и сообщения рекрутеру (расширяет 7.2–7.3)

- «+ Новая карточка»: ссылка **или текст** вакансии, рекрутер (имя, профиль, канал), **скриншоты** (Supabase Storage, приватный bucket, RLS по владельцу). AI (приватный ключ, vision) извлекает компанию, роль, рекрутера, даты и предзаполняет карточку.
- «Написать рекрутеру»: AI-текст на основе CV + анализа вакансии в форматах: LinkedIn connection note (≤300 символов), InMail, Telegram, email; язык и тон; «Отправил ✓» пишет исходящее сообщение в историю и запускает follow-up таймер; «Пингануть» генерирует напоминание с учётом переписки.

### 12.5 Анализ карточки (расширяет 7.3, 7.4)

- Кнопка **«🔍 Анализ»** (и автоматически при новом входящем): AI читает вакансию, переписку и текст скриншотов и возвращает предложение: колонка + уверенность + причина, лейблы, даты (интервью, дедлайн тестового), следующий шаг + дата напоминания, причина отказа (таксономия 7.4) с разбором «что улучшить», черновик ответа.
- Применение: «Применить всё» или по пунктам. **Автопилот** (применять при уверенности ≥ 0.9) — настройка пользователя, **по умолчанию выключен**.

### 12.6 Почтовые ящики и мессенджеры (заменяет 3 «Gmail OAuth — подпроект 5» и расширяет 6.5)

- Пользователь подключает **любое количество ящиков в любой момент** (Настройки → «Почтовые ящики»): **Gmail OAuth** (`gmail.readonly`; до публичного запуска — режим тестирования Google, до 100 тестовых пользователей; перед коммерческим запуском — проверка CASA или только пересылка), **Microsoft/Outlook OAuth** (`Mail.Read`), **пересылка** на персональный адрес `<token>@in.<domain>` (один адрес на пользователя, исходный ящик — по заголовкам).
- Таблица `mailboxes(id, user_id, provider: gmail|outlook|forwarding, address, status, last_synced_at, error, encrypted_refresh_token, created_at)`; токены шифруются (pgsodium/Vault), отключение одной кнопкой, статус и «Синхронизировать сейчас».
- Читаются **только письма о работе**: фильтр по отправителям (djinni.co, linkedin.com, dou.ua, work.ua, robota.ua, jooble, домены компаний из карточек пользователя) и ключевым словам; остальная почта не загружается и не хранится.
- Уведомления площадок о сообщениях рекрутеров (Djinni, LinkedIn, Work.ua, robota.ua, DOU) распознаются отдельными парсерами; письмо привязывается к карточке по ID вакансии в ссылке, названию, компании/домену, рекрутеру; иначе — во «Входящие» (привязать/создать карточку). На карточке — «💬 новое сообщение», счётчик непрочитанных на доске, уведомление в Telegram, автозапуск анализа.
- Логин/пароль от Djinni, LinkedIn и т.п. **не запрашиваются и не хранятся**.
- **Telegram:** пользователь пересылает сообщение рекрутера боту → бот предлагает карточки для привязки кнопками → сообщение сохраняется и анализируется. Чтение личных чатов не делается.
