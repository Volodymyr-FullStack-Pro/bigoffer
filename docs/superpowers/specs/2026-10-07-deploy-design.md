# Деплой BigOffer (Етап 1 «повного робочого флоу») — дизайн

**Дата:** 2026-10-07 · **Статус:** затверджено власником у чаті · **План:** `docs/superpowers/plans/2026-10-07-plan-8-deploy.md`

## Мета

BigOffer працює 24/7 у хмарі на безкоштовних тарифах: сайт доступний з телефону й ноутбука, парсер збирає вакансії щогодини без ноутбука власника, платний AI для особистих даних має жорсткий денний ліміт.

Це перший із трьох етапів: 1) деплой (цей документ), 2) обсяг і швидкість (План 6d: всі ключові слова + варіанти назв, Jooble, Adzuna, LinkedIn і Work.ua в хмарі, частота опитування, фільтр «нові за 24 год»), 3) Telegram-бот (мінімальний План 6b: прив'язка, миттєві сповіщення, ранковий дайджест).

## Рішення власника

- Хостинг: **Vercel Hobby** (сайт), **Supabase Cloud Free** (база, вхід, Storage), **Trigger.dev Cloud Free** (парсер і AI за розкладом, $5 кредиту/міс), **Resend Free** (SMTP для magic link — після покупки домену).
- Старт **з нуля**: локальні дані не переносяться; власник реєструється на проді як звичайний користувач.
- Приватний AI: **Gemini, платний ключ**, ліміт **100 приватних AI-запитів на добу (UTC) на користувача**, змінна `PRIVATE_AI_DAILY_LIMIT`. Публічні дані (вакансії) — безкоштовний ключ, як і раніше.
- Вхід на старті — **Google OAuth**; magic link через Resend, коли буде домен (лише конфіг Supabase, без коду).
- Прод деплоїть власник: злиття `develop → main`. Агент у прод не пушить.

## Архітектура

## Зміни в коді

1. **Ліміт приватного AI.** Таблиця `ai_user_usage(user_id, day, requests)`, лише `service_role`. Функція `consume_private_ai(p_limit int) returns boolean` (security definer, `search_path = ''`, користувач = `auth.uid()`, доба = UTC) — атомарно `insert … on conflict do update … where requests < p_limit`, `true` якщо запит дозволено. Веб викликає її серверним клієнтом користувача **перед** кожним приватним викликом LLM (розбір CV, apply kit, відповіді на форму, повідомлення рекрутеру). Понад ліміт LLM не викликається, дія повертає помилку `ai_limit`, UI показує локалізоване повідомлення (en/uk/ru) з часом скидання. Лічильник рахує спроби (невдалий виклик теж витрачає одиницю — захищає від зациклення).
2. **Пряме завантаження CV.** Vercel обмежує тіло запиту 4.5 МБ, а CV до 5 МБ. Браузер завантажує PDF прямо в Storage (`resumes/<uid>/<uuid>.pdf`; бакет уже обмежує 5 МБ і `application/pdf`, політика дозволяє лише власну папку), потім server action `registerCv(path, fileName)` перевіряє, що шлях у папці користувача, завантажує об'єкт, перевіряє розмір і сигнатуру `%PDF-`, далі — як зараз (запис у `resumes`, розбір, профіль). Невалідний файл видаляється.
3. **Перевірка середовища** вже є: `apps/web/src/env.ts` (Zod) падає на старті з назвами відсутніх змінних — нового коду не треба; `.env.example` доповнюється `PRIVATE_AI_DAILY_LIMIT`.
4. **CI-деплой.** `.github/workflows/deploy.yml` на `push` у `main` (і `workflow_dispatch`): job `migrate` (Supabase CLI: `link` + `db push`), job `trigger` (`needs: migrate`, `trigger deploy` з `apps/jobs`). Секрети: `SUPABASE_ACCESS_TOKEN`, `SUPABASE_DB_PASSWORD`, `SUPABASE_PROJECT_REF`, `TRIGGER_ACCESS_TOKEN`; змінна `TRIGGER_PROJECT_REF`. Без секретів job падає з явним повідомленням.
5. **Документація.** `docs/deploy.md`: покроково для власника — Supabase (проєкт, Auth URL, Google OAuth), Vercel (імпорт, Root Directory, змінні), Trigger.dev (проєкт, змінні), GitHub (секрети), Gemini (окремий проєкт, бюджетне сповіщення $5), Resend + домен (пізніше). Таблиця всіх змінних по сервісах.

## Не входить

Перенесення локальних даних; власний домен; Telegram-бот; нові джерела — наступні етапи.

## Помилки та безпека

- Фейковий AI у production заборонений (уже є).
- Користувач не має прав на таблицю `ai_user_usage`; функція рахує лише власний лічильник (`auth.uid()`), тож прямий виклик RPC користувачем може тільки витратити його ж ліміт, а AI-виклик робить лише сервер.
- Секрети лише в налаштуваннях сервісів і GitHub Secrets; у репозиторії — тільки назви змінних.

## Тестування

pgTAP для `ai_user_usage`/`consume_private_ai` (ліміт, атомарність, приватність таблиці); unit-тести веб-хелпера ліміту; E2E: завантаження CV через новий шлях і повідомлення про ліміт (`PRIVATE_AI_DAILY_LIMIT` у конфігу E2E); `actionlint`-перевірка workflow, якщо доступний; повний прогін як завжди.
